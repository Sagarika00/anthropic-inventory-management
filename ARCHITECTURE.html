Request & data flow

  1. User changes a filter. The shared FilterBar updates state exposed by the useFilters composable (Time Period, Location/Warehouse, Category, Order Status).
  2. A view reacts. Dashboard / Inventory / Orders / etc. call the matching method in api.js, passing the active filters.
  3. api.js builds the request. Filters equal to 'all' are dropped; the rest become URLSearchParams on a GET to http://localhost:8001/api/…
  4. FastAPI routes it. The endpoint reads the in-memory list, then runs apply_filters() (warehouse / category / status, case-insensitive) and filter_by_month() (direct month 2025-07 or quarter Q3-2025).
  5. Aggregation, if any. Summary/report endpoints compute totals on the fly (inventory value, low-stock count, quarterly revenue & fulfillment rate, monthly trends).
  6. Pydantic validates the response against the declared model and FastAPI serializes it to JSON.
  7. The view stores & derives. Response lands in a ref; computed properties produce the numbers, groupings and SVG chart geometry that render in the template.

Inventory has no time dimension, so its endpoint accepts only warehouse & category — not month.

Cross-cutting

  • Revenue goals: $800K/month, $9.6M YTD
